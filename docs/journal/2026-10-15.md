# 2026-10-15

## KAV-87 — the staging proof

Started staging at about 15:55 UTC on the merged build (`sha-b36c4be`, PR #168 and the pin in PR #169). About
2 h 45 min of staging in all, roughly $0.12, plus the dev server for the tests.

**What worked.** The model pod and the worker came up on the new image; the worker started before the model was
ready, retried, and indexed 78 runbook chunks by itself. The out-of-memory game day: one proposal from the worker
about 2 min 35 s after the failure began, none after that. The full-disk game day: a person is told, nothing proposed.
Model off: the incident stayed open, `KavalDiagnosisBacklog` fired (the poller opened `kaval_diagnosis_backlog` at
18:09:51), the correlator and executor carried on. Model back: ready in 35 s, the one proposal filed at the worker's
next try, alarm cleared. Clean second run: the worker's proposal approved 6 s after it appeared, limit raised 200 s
after the failure began, the program stayed up.

**Measured.** Idle node 1,640 to 1,725 MB used; with the model loaded about 2,840 MB used and 780 MB available at the
worst moment; the model unloads 5 minutes after use. One model call 36 s (limit 90 s). Processor credits: balance rose
0 to 29.5, surplus charged $0. Full table in ADR-0055.

**What went wrong.**
1. The worker's database account could not read `outcome`, which the context builder reads once a similar incident
   exists. It crashed on the second incident (restarted, then idled). The laptop uses an administrator account, so no
   laptop test could show it. Fixed with one read-only grant and a test that names every table the worker reads
   (PR #170); applied to the running staging by starting the node's bootstrap service.
2. My approval came 17 minutes after the proposal; staging gives 15. It was refused as expired, as designed. The
   by-hand switch then turned out never to reach the pod that files the proposal. Fixed in the same PR.
3. I edited `chaos.sh` while a game day was running it; bash reads scripts as it goes, so the running copy hit a
   syntax error and cleaned up early. The approved fix then found nothing to fix ("not found") and failed safely.
   Never edit a script that is running.
4. Twice my own watchers misread the log (matched old failure lines; one never wrote its file). Cost: minutes, not
   correctness. A units slip too: my output filter dropped the "µ" and made 24 µs health checks look like 24 s.

**Decision for Roshan.** Prod switch-on waits for the numbers to be seen: model about 1.13 GB while loaded, about
850 MB expected to stay available on prod's node at the worst moment, $0 recurring.
