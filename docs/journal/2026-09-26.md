## Phases 1–3 move to an AWS dev server (ADR-0007, `KAV-29`)

Before starting `KAV-22`, two questions came up: which local model to use, and whether the laptop
could cope. **Model:** Gemma 3 1B is a generation behind. Gemma 4 E2B (April 2026), Qwen3 1.7B
and Llama 3.2 1B are all candidates within the 4 GB node's budget, and NVIDIA's "Nano" models are
far too big for it. The shortlist gets measured and Phase 2's evals pick the winner. **Laptop:**
it could cope (16 GB, 7.6 GB for Docker, against a ~2.5 GB need). But Roshan chose to run
the stack on AWS anyway, accepting the cost, so every measurement comes from the real hardware.

- **Built:** `infra/modules/devbox` + `infra/envs/dev`. It's a `t4g.medium` on-demand in
  ap-south-1a, default VPC, **zero inbound rules**, reached only through SSM Session Manager (SSH
  inside the tunnel), IMDSv2, 30 GB encrypted gp3. It stops itself after 60 idle minutes. Prices
  came from the AWS Price List API: $0.0224/hr, ~$5/month at 20 hrs/week. The project
  projection goes from ~$52 to ~$67.
- **Docs first, then the apply.** ADR-0007, the budget plan, roadmap, dashboard posture, concept
  pages, README and repo guide were all written and committed before anything existed in AWS.
  Roshan asked for exactly that before approving.
- **The Free Plan refused `t4g.medium`** (`InvalidParameterCombination: not eligible for Free
  Tier`). A dry run had passed, because dry runs check permissions, not plan eligibility. Roshan
  upgraded the account, after checking **Billing → Credits**: **$140** ($100 plus two $20
  credits earned by Phase 0's Lambda and budget work), $0 used, **expiring 2027-09-11**. That
  corrects Lab 01's "$100, 182 days": 182 days was the Free *Plan*, not the credit.
- **A serious bug found on the first boot.** The idle-reset unit wrote `/bin/bash` instead of a
  timestamp, because systemd expands `%s` in unit files to the user's shell. The idle check would
  then fail on every run, and **the server would never have stopped itself, while looking
  protected.** Fixed with `%%s` (checked in the rendered template, not assumed), plus a guard
  that resets on any non-numeric value. A smaller one: Terraform's "No outputs found" warning goes
  to standard output, so it filled the Makefile's instance-ID variable. That's now filtered to
  `i-…`.
- **Proven, not assumed.** With the limit temporarily at 2 minutes, the server stopped itself
  about 7 minutes after the last disconnect. Its own log said `idle for 417 s, stopping the
  instance`. `make devbox-up` brought it back in 30 seconds. The boot reset wrote a timestamp
  3 seconds after boot, and the limit went back to 60. `docker --context kaval-devbox run
  hello-world` from the laptop pulled the `arm64v8` image.
- Laptop side: Session Manager plugin 1.2.835.0 via winget, `~/.ssh/config` entry, dedicated
  key `~/.ssh/kaval-devbox` (outside the repo), Docker context `kaval-devbox`. Docker Desktop
  is stopped; only its command-line tool is needed.
- Full walkthrough: [Lab 03](../labs/lab-03-aws-dev-server.md).

## The $24 hard stop is armed for the first time (`KAV-30`)

Roshan asked what the "$24 emergency shutdown" actually was. Reading the code gave an honest and
slightly embarrassing answer: with an empty target and `DRY_RUN=true`, **it could not stop
anything**. It had proven its wiring in Phase 0, and that was all. I'd been describing it as
protection it wasn't giving.

- **Extended and armed** (Roshan approved). The Lambda now also **stops** (never terminates)
  running `Project=kaval` instances that aren't in an ASG, and it's armed for real. The ASG path
  is unchanged and stays dry-run until Phase 4. IAM gains `ec2:DescribeInstances` and
  `ec2:StopInstances`, the latter conditioned on `aws:ResourceTag/Project = kaval`.
- **Plan to prod: 1 added, 2 changed, 0 destroyed.** The "1 added" was a surprise. The **SNS

## The production database gets its own server; ceiling $25 → $40 (ADR-0008, `KAV-31`)

Roshan asked whether production would really keep Postgres on the same server as the app, since
the project should match a real corporate setup. It would have: the design ran Postgres inside the
single spot k3s node. That couples the audit trail to a node built to be thrown away, and to the
local model's memory spikes.

- **Priced first** (AWS Price List API, ap-south-1): RDS `db.t4g.micro` ~$18/mo Single-AZ, ~$36/mo
  Multi-AZ; self-managed Postgres on an EC2 `t4g.small` ~$14/mo. **Roshan chose self-managed EC2
  and a $40 ceiling.** RDS was declined because it costs more for the same availability and hides
  the operations work this project exists to teach.
- **Designed, not built.** [ADR-0008](../adr/0008-production-database-on-its-own-server.md): on-demand (never
  spot), a separate encrypted data volume with `prevent_destroy`, 5432 open only to the app node's
  security group, no SSH, TLS, Parameter Store secrets, per-service roles, termination protection,
  DLM snapshots plus the nightly dump. The server is built in Phase 4 (`KAV-32`, 8 points, 12
  acceptance criteria); Phase 1 keeps Postgres in a container on the dev server.
- **No idle stop for a database.** Roshan asked about auto-stop and about backing up at every
  stop. A database's user is the app, so an idle stop would never fire or would cut the app off.
  It stops only via `make down`, a paused-posture nightly stop, or the hard stop, and **each takes a
  snapshot first**. A start-up health check restores the snapshot **only if the check fails**:
  stopping keeps the EBS volume, so a normal start has nothing to restore. Stated honestly, this
  gives no data loss and a clean resume, not uninterrupted service while paused.
- **Prod budget applied** after showing the plan (0 add, 1 change, 0 destroy): the limit is $40,
  alerts are $30 / $35, the hard stop is $38, and the forecast alert is $40. Verified with
  `describe-budget` and `describe-notifications-for-budget`. There's no drift. The hard stop was
  re-fired: the dev server went running → stopped in ~10 s.
- **Projection corrected in the open.** The plan estimated ~$100–105 total. Itemised, it's
  **~$110** (DB paused ~$12, always-on ~$29, staging DB ~$1), leaving ~$30 of the $140 credit.
- **The sweep found stale facts in code, not just prose.** The dashboard's cost gauge had
  $18/$22/$24 hard-coded in `dashboard.py`; it now reads the thresholds from `dashboard.toml`.
  `cost-report.sh` defaulted to a $25 ceiling. `dashboard.toml` still said `provisioned = false`
  a day after the dev server went live. The restore runbook, which the agent will also retrieve
  from, described Postgres as a cluster pod. It was rewritten for a database server, with a
  snapshot-restore path.
- **The habit is now a rule:** `CLAUDE.md` gains Definition of Done item 10, *documentation sweep,
  unasked*. Roshan had to ask "is everything getting documented everywhere" too many times.
