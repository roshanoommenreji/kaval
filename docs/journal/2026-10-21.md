# 2026-10-21

## Back after two days: CI on main had a date time-bomb (KAV-95)

Status on return: staging had parked itself (no server, database stopped, data kept), the test disk
`vol-09b0b4178d6d7994f` and its backup `snap-0717...` were exactly as left, the month's spend was $9.10, and two
pull requests were open: the release robot's pin (#211) and a Dependabot bump (#212).

- **Found:** #212's "test" check failed, but not because of the library: `test_a_step_handed_over_is_left_to_the_worker_then_
  retried_only_if_nothing_came_of_it` (and `test_a_no_is_not_asked_again_for_a_week`) failed on 2026-10-20. Cause: the
  planner measured its pauses ("not again for 48 hours / a week") from `action.created_at`, which the database stamps with its
  real clock, while the tests move a pretend clock (fixed at 2026-10-19). The tests passed only on the day they were
  written. From 2026-10-20 every pull request would have failed CI.
- **Fix:** the planner stamps the action with its own clock (`file_proposal(..., now)`), so the pauses and the clock
  are the same clock. A new test runs the retry sequence from a pretend date in 2024 and one in 2041 and checks the
  action is stamped with the planner's time. Verified: without the fix four tests fail, with it they pass.
- **Second form of the same bug:** the whole-ladder test also started its pretend clock on 2026-10-19, and the gateway
  (correctly) refuses an approval on a proposal older than a day by the REAL clock. It now starts at the real "now".
- **Lesson:** a test that moves a pretend clock must make every part that reads a clock use that same one, and a date
  written into a test is a date it will fail on. The full suite (1496 tests) was run on the day of the fix.
- **Cost:** $0.
