## Phase 7 starts: the EKS lab is built, tested and planned, with nothing created in AWS (`KAV-101`)

- **Asked:** "go" on the Phase 7 plan (real EKS for one session, the identical chart, IRSA, the load balancer controller, a timer, a clean-up check), with the plan shown first and the cost first.
- **Priced before writing (2026-10-28):** the EKS control plane is $0.10 an hour (about $73 a month) from creation; a Kubernetes version past standard support is $0.50 an hour; `t4g.medium` is $0.0224 an hour. 1.35 is in standard support to 2027-03-27 and is what CI already renders the chart against. A six-hour session is about $1.2 to $2; the roadmap's $4 stays as the cap, and three sessions replace the old $15 placeholder with about $6.
- **Built:** `infra/modules/eks-lab` (control plane, managed node group of two arm servers, add-ons in order, the identity endpoint and four per-pod roles; AWS's published load balancer controller policy for v3.5.0 committed unedited), `infra/envs/lab-eks`, `infra/modules/lab-reaper` (a timer that scales to zero at 4 hours and deletes at 6; 12 tests), `scripts/ops/lab_sweep.py` (`make lab-sweep`, billing vs leftover, 6 tests), and `deploy/gitops/lab-eks` + `deploy/environments/lab-eks` (the same chart; the IRSA label added by a post-renderer in the lab's own release; the network policies behind a hand-applied switch). `scripts/dev/test_lab_eks.py` (10 tests) turns "the chart is not edited for the lab" into a failing test.
- **Decided:** [ADR-0067](../adr/0067-the-eks-lab-is-ephemeral-has-its-own-timer-and-is-proven-clean-by-a-label-sweep.md). The nightly brake does not cover an EKS cluster (its server group has a generated name and the control plane is not a server), so the lab carries its own timer. The proof of IRSA is the smallest honest one: the executor's role reads one named parameter, and a different service account is refused. The chart gets no edit; anything the strict rules break becomes its own story.
- **Plan read (not applied):** `make lab-plan` against the real account: 44 to add, 0 to change, 0 to destroy, the API reachable only from the laptop's address. The numbers and what was found on the way are in [Lab 65](../labs/lab-65-building-the-eks-lab-before-spending-anything.md); the procedure for the live run is [runbooks/lab-eks.md](../runbooks/lab-eks.md).
- **Found on the way:** a Secret-based database password for the lab would have failed the CI render of every environment (and Flux's inline values override `valuesFrom` anyway), so the lab uses a plain throwaway like `local`; adding the `lab-eks` environment failed the test that keeps the waste scan's and the removal worker's copies of the tag policy equal to the real one, and both copies were updated (the worker still acts only on its own environment).
