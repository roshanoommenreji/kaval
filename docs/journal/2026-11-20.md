## After v1: moving the three flagged chart images (`KAV-169`, `KAV-170`, `KAV-171`)

"go, plan KAV-169" on 20 November; the plan was shown, he said "go", then "GO" to the dated exceptions. [ADR-0107](../adr/0107-the-chart-images-move-to-their-newest-releases-and-the-leftovers-get-end-dates.md), [Lab 110](../labs/lab-110-moving-the-chart-images-past-the-problems-the-weekly-watch-found.md).

- **Scanned every candidate before changing anything.** Prometheus v3.16.0: 14 problems down to 1; Ollama 0.40.16: 55 down to 3; pgvector 0.8.7 on PostgreSQL 16 / Debian bookworm: 27 down to 26, all in `gosu`, which the official PostgreSQL image (rebuilt 18 November) has too. Nothing was clean, so the leftovers became 28 dated, file-scoped exceptions (two weeks for the small ones, four for `gosu`). Checked against the three real images with Trivy: Prometheus and the database come back with nothing.
- **Planning found something the weekly watch could not see.** The chart's database image is used only by the local cluster and the lab. Staging's and production's databases run on their own servers, started by a script that is read once and that Terraform ignores afterwards, and the tag floated. So an edited pin reaches staging (rebuilt every time) but never production's server. Built `scripts/ops/db-image-refresh.sh` (and `-remote.sh`): a go-gated step at production's start-up that pulls the pin first, rewrites only the image in the unit, restarts the database and prints the server version. It refuses anything that is not a pinned pgvector PostgreSQL 16 image. Stayed on bookworm on purpose: a newer Debian sorts text differently and can break indexes.
- **The pins now live in six places, and a test keeps them equal** (`test_third_party_image_pins.py`), until `KAV-170` (Dependabot for chart images) is built.
- **The model check was the hard part.** Running the repo's own eval sets on a laptop needed OPA, a database, the model volume shared across both Ollama versions, and a warm-up call (the first request takes ten seconds and the tool gives up at thirty): four failed runs before one worked. Result: golden 20 of 20 on both, same scores. One gate failure on both versions (the smuggling case: the model copies "not reversible, account-wide" from planted text onto a harmless restart, which policy refuses) is not caused by the upgrade and is filed as `KAV-171`.

The weekly watch stays red until the promotion, because it also reads the commit production is pinned to.
