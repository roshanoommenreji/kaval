## The cost reader (KAV-92)

[ADR-0060](../adr/0060-the-cost-reader-the-server-asks-aws-and-the-cluster-never-holds-the-login.md),
[Lab 57](../labs/lab-57-the-cost-reader.md), [runbook](../runbooks/cost-reader-not-pulling.md).

**The design question was identity.** No Kaval program in the cluster can talk to AWS, on purpose. The reader needs
one call, once a day. Chosen: the server's own job (the pattern of the still-alive alarm) borrows a separate role that
can only read costs, and leaves the answer in one ConfigMap; a new pod with no AWS login reads it and writes the
signals. Rejected: sharing the server's role with every pod, a long-lived key in a Secret, a function outside the
cluster (it cannot reach the database without a paid add-on). Pod identity is the likely answer for `KAV-95`'s write
actions and is not blocked.

**What the real bill changed.** One real pull (14 days) was recorded as a test fixture and drove three rules: only days
at least two old (the newest day is always partial and the table is append-only), nothing for zero (7 of 18 services
ever cost anything), and a spike must also be 25 cents above the usual (run against the real bill, the old ratio-only
rule called a 20-cent move on the compute line a spike). The account's own bill shows the reader's cost: "AWS Cost
Explorer" 10 cents on 16 October, from the tests that built it.

**Built and tested on the laptop, nothing live yet:** the collector module and its 50 tests (against a real Postgres),
the server's script with 21 tests (cap of 60 stops, the 60th request is allowed, the borrowed login is the only one used
for the billed call, AWS's error text never reaches the cluster), the chart (off unless switched on, may get one
ConfigMap by name, no AWS login), three alert rules with promtool tests (a failed try that the next one fixes stays
quiet), the Terraform module (one permission) wired into staging and production, and the size of the server's start-up
script (it is now about 15.3 KB of the 16 KB EC2 allows; a test fails before the next addition does). Full suite: 1,091
passed. Docker Desktop had to be started on the laptop for the database and rule tests.

**Cost:** about 31 requests a month, $0.31, at most $0.60; no new server.

**Open (next):** production at its bring-up (with the `KAV-90` checks). Switching on AWS Cost Anomaly Detection is a
console step after its price is confirmed.

## KAV-93 built on the laptop (same day, on Roshan's go to the plan)

A read-only look at the real account first: only `Project` was active as a billing label (so the bill could not be split
by environment), and **12 of Kaval's 103 resources were missing a label**: the staging server (the Auto Scaling group
launches it with `Name` and `Project` only), its disk (nothing at all), and 10 pre-stop snapshots made by the two stop jobs
(no `Env`, no `ManagedBy`). 33 more belong to `stock-trader`, which shares the account and is counted, never touched.
Found on the way that AWS now has a tag backfill, so the learn page's "never retroactive" was wrong and was corrected.

- **Decision:** three required labels, fixed values, two layers of enforcement (a test before building, a scan after),
  no AWS Config / organisation policies (cost; needs an Organization), no `Owner`/`Component` (one owner; `Name` already
  says which part). [ADR-0061](../adr/0061-every-resource-carries-three-tags-and-the-bill-is-split-by-them.md).
- **Built:** `scripts/ops/tag_policy.py` (rules + the offline check; run on the code before the fix it reports exactly the
  9 defects the live scan found), `tag_scan.py` (`make tag-scan`), `showback.py` (`make cost-showback`), 33 tests with the
  negative cases, the node module labelling instance + disk + group, both stop jobs adding `ManagedBy`.
- **Staging plan read, not applied:** 3 changed in place (launch template, group, idle-stop code), 0 added, 0 destroyed.
- **Open:** the staging apply and a freshly launched server proving the labels; switching on `Env`/`ManagedBy` as billing
  labels plus the backfill (own go); labelling the 10 old snapshots and the staging disk (own go); production at its
  bring-up. [Lab 58](../labs/lab-58-tags-and-the-showback-report.md) lists them as unticked boxes.
