## A genuinely dumb Windows gotcha, documented so nobody else loses ten minutes to it

`aws logs tail "/aws/lambda/$FN" --profile kaval` failed on Git Bash with a confusing
`InvalidParameterException` claiming the log group name failed a regex — the string was clean
(checked with `od -c`, no hidden characters). Actual cause: MSYS silently rewrites a leading-`/`
argument into a Windows path before it reaches `aws.exe`. Fix is `MSYS_NO_PATHCONV=1` prefixed
onto the command. Added directly to Lab 01 so a stranger on Windows doesn't hit the same wall.

## The SNS confirmation, twice

First confirmation succeeded (screenshot showed a real subscription ARN), but minutes later an
"Unsubscribe Confirmation" email arrived — it had been deactivated. Best guess: the confirmation
success page itself carries a "click here to unsubscribe" link right below the success message,
and it's an easy thing to click by accident while looking at the page.

Checked two ways before trusting either read: `get-subscription-attributes` on the specific ARN
kept returning `PendingConfirmation: false` even after the unsubscribe (stale cached data on a
just-deleted resource, misleading on its own), while `list-subscriptions-by-topic` correctly showed
the endpoint's `SubscriptionArn` as the literal string `Deleted` — the two disagreed, and the list
call turned out to be the trustworthy one. Re-subscribed via `aws sns subscribe` directly (not
another email link) to sidestep the same mistake twice; AWS reactivated the *same* underlying
subscription ARN rather than minting a new one, which also means — corrected from what I said in
the moment — Terraform's state already matches reality, no drift to expect on the next plan.

Confirmed for real this time by checking both signals together and requiring them to agree:
`PendingConfirmation: false` **and** the list no longer showing `Deleted`. Worth remembering as a
pattern — a single AWS API read after a just-changed state can lie by omission (stale, not wrong
exactly, just late); two independent reads agreeing is the actual bar for "confirmed."

`KAV-18` already correctly said this AC item was done from the first (later-undone) confirmation —
content didn't need changing, just worth knowing the story behind that checkbox.
