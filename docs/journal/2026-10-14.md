## Phase 5: teaching the model which fixes exist (KAV-84, ADR-0054, Lab 51)

**What.** The out-of-memory game day found that the local model names the cause and proposes nothing. This slice
tells it which fixes exist and measures the change with `make evals` before and after.

**What happened.** The first try (the list in the system prompt) changed nothing: 0 of 8 before, 0 of 8 after, no
action in any of 40 replies. The reason was `actions` being an optional field, which a 1B model always leaves
out. After that, each plausible fix failed in its own way: the list in the system prompt was followed in 1 of 5
tries and at the end of the message in 5 of 5, but with invented targets; a worked example had its target copied
onto other workloads; showing all three fixes made it list all of them or invent a fourth; showing only the right
one and letting it decline got a fix in 3 of 15 tries. What worked (15 of 15) was choosing the fix from the incident's
cause, which the correlator names and a log line cannot change, and narrowing the reply format to exactly that
fix and the incident's own workload, with a second check on the reply and one corrective retry.

**Built.** `kaval_agent/fixes.py` (the one list, with the causes each fix answers, and a test against the executor's
own list), `actions` now required, the fix section last in the message, `diagnose()` narrows the schema per
incident, the evals score the fix (right fix aimed at the right workload, other fixes alongside, none where Kaval
has none, types off the list) and run the old prompt beside the new one (`evals/baseline.py`, `make evals
PROMPT=both`).

**Measured, three full runs.** Right fix 0 of 8 to 8 of 8 each time; quiet where Kaval has no fix 6 of 6 both; 0 of 14
actions off the list; no never-class action; the four injected instructions were never proposed. Prompt grew from
about 770 to 930 tokens per case. **Side effect:** stated confidence rose (mean 0.76 to 0.88; 60 percent of replies
at 0.9 or more, against 10), and the two sparse cases, failing since Lab 13, now say 0.95.

**Found on the way.** Nothing in the cluster calls the model: the agent only groups signals, and staging's game
days file proposals by hand. This slice improves what the step suggests; running it for every new incident is
`KAV-87`. Confidence is `KAV-88`.

**Cost.** The dev server for about two hours, about 6 cents plus any surplus-CPU charge (not yet read off the
bill). Both stopped afterwards.

**Not done.** The Bedrock path is told the same thing but its reply is not narrowed or re-checked (it cannot run
live, `KAV-44`). The crash-loop case with two candidate fixes has no golden case. No held-out set.
