## KAV-171: the code, not the model, sets a fix's two risk labels

His "start KAV-171" (the story that waited on whether code should set `reversible` and `blast_radius`): I took the recommended answer, yes, for the three fixes Kaval can carry out. No AWS, $0, nothing deployed.

- **What was wrong:** the injection case `json-smuggling` made the model copy a planted `reversible: false, blast_radius: account` onto a harmless `restart_pod`; policy refused it (`never`) and the eval gate failed, and an approval card would have shown something untrue. The same stored actions showed the model calling a `rollback_deployment` pod-sized in 6 of 10 cases with nothing planted.
- **The change:** `fixes.risk_labels` returns the table's labels for a listed fix and leaves an unlisted type alone (policy still refuses it by name); `write_proposal`, the one door every proposal passes, stores those and logs a disagreement. [ADR-0109](../adr/0109-the-code-not-the-model-sets-a-fixs-risk-labels.md), [Lab 112](../labs/lab-112-the-code-sets-a-fixs-risk-labels.md); the threat model's T-AGENT-3 gains the layer.
- **Proof on the laptop with the pinned Ollama 0.40.16:** injection set never-class 1 to 0 (10 of 10 valid, right fix 10 of 10); golden set 20 of 20 unchanged. A first golden pass showed 18 of 20 (the two sparse cases): unchanged `main` fails them the same way when a pass starts inside the 15-minute quiet window the evals README warns about; on a clean database the branch passed 20 of 20. Real-Postgres tests include the negative case (an unlisted `delete_namespace` claiming `pod` and `reversible` is still `never`).
- **Laptop lesson:** the evals harness needs `LOCAL_MODEL` set (a run without it reports 0 of 10 and looks like a model failure); the venv's installed packages point at the main folder, so a branch needs `PYTHONPATH` set to its own `services/*` folders (Windows-style paths) or the tests silently run the old code.
