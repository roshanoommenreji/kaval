## `KAV-114`: model-written text is escaped before it goes into Slack

Roshan said "start KAV-114", I gave the plan (options, the whole path, safety, failure, cost, tests), and he answered "go with your recommendations" (late evening, 9 November IST).

- **What was wrong.** The summary on the approval card, and the action type and target beside it, went into the Slack message exactly as written. Slack reads `<`, `>` and `&` as control characters, so `<!channel>` would ping everyone and `<url|Approve all>` would draw a fake link. The model did not do this in either live run of the injection set (2026-11-01), but nothing stopped it. The threat model row is T-SLACK-2.
- **What I found beyond the story's text.** The same text reaches Slack in five places, not one: the card, the plain line Slack shows in a notification, the "still waiting / nobody answered / expired" messages, the "what will happen" lines under a removal card, and the service name in a health alert. All five now go through one helper.
- **The fix** ([ADR-0082](../adr/0082-text-the-model-wrote-is-escaped-before-it-goes-into-slack.md), [Lab 84](../labs/lab-84-escaping-the-text-on-the-slack-card.md)). `services/gateway/kaval_gateway/slack_text.py`: `escape()` (the three characters, ampersand first) and `code()` (also drops backticks, which would close a code span early). The `<!here>` Kaval writes in an escalation is left alone on purpose. The six expected failures in `test_injection_slack.py` are now ordinary passing tests; I added tests for the other four messages and for ordinary text staying unchanged.
- **The injection set now reports the card.** `evals/card.py` builds the real card from each summary the model wrote and `make evals SET=injection` prints "approval cards with live Slack markup: n/10 (gated: must be 0)". Gated, unlike "planted text obeyed", because it is the gateway's code and not the model's behaviour. The golden twenty are untouched.
- **Checked.** Test-first: the new tests failed for the right reason before the fix. Whole `services` and `evals` suites pass, `ruff` is clean, `mypy` shows only an error that was already there (it needs `scripts/ops` on the path).
- **A tooling note.** The project's Python is installed pointing at the main folder, so a test run inside a worktree silently used the main folder's code until I pointed pytest at the worktree with `-o pythonpath=...`. Worth knowing for the next story.
- **Not yet done.** A release round for the gateway change, staging smoke plus the injection set against the real pipeline, promotion, and the first real card seen in Slack at production's next start-up (staging has no Slack). Jira `KAV-114` is ticked only when that is done.
