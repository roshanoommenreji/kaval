# 2026-11-02

## `KAV-115`: a login on the approval route (built, part 1 of 3)

`KAV-112` found that `POST /v1/actions/{id}/decisions`, the route that records an approval, asked nobody who was calling, and that the chart used by staging and production has no network rules. Roshan picked it as the next free item.

The plan was two controls, so one covers the other's miss: a token on the route, and network rules around it. A look at how secrets already reach the cluster showed a third piece: the node's bootstrap rebuilds every Secret from Parameter Store on each boot and on a six-hour timer, so a hand-made token would be lost at the first replacement. The token therefore needs a Terraform-made home in Parameter Store too. Three pull requests, each through staging before production: the login (this one), the token's home, the network rules. [ADR-0073](../adr/0073-the-approval-route-gets-a-login-and-the-namespace-gets-network-rules.md).

What this one does: the route needs `Authorization: Bearer <token>`. It is shut (503) when no usable token is configured, compares in constant time, runs before the database or the body is touched, and never writes the token to a log, a reply or a metric. The actor is stored as `api:<name>` so a caller cannot pose as `slack:<name>`. The chart reads the token from the Secret `kaval-approver` (optional, so a missing Secret leaves the route shut rather than crash-looping the pod); `make approve` reads it from an environment variable, never an argument; `make chaos-approve` reads it from the cluster on the node so it never reaches the laptop. Tests: 30 for the login (no database), the existing approval tests now send the token, one new one for the `api:` prefix, chart tests for staging, production and the empty default. Run against a throwaway local database: 127 gateway tests pass (6 expected failures are `KAV-114`); the wider run passes 1,113.

Two small things the work turned up. A new metric label (`why`) failed the existing "nothing from data on the metrics page" test the moment the gateway and the shared tests ran in one process; the label is now `outcome`, which that test already allows. And `services/shared/tests/test_metrics.py` and `kaval_shared/metrics.py` both say Flannel enforces no network policy; k3s's own documentation says it ships a policy controller that is on unless switched off, and ours is not switched off. To be proven live in the third part and then corrected everywhere, including the comment at the top of the EKS lab's network-policies file.

Until the second part lands an environment has no token, so its approval route answers 503 and `make approve` cannot work there (Slack still does). The two are promoted to production together.

## `KAV-115` part 2: the token's home (built)

#298 merged. The second pull request makes the token a thing that exists without anyone typing it. A new Terraform module (`infra/modules/approver-token`) generates it (43 letters and digits) and stores it in Parameter Store at `/kaval/<env>/approver/token`; staging and production each use it and let the node's role read exactly that one parameter; the node's bootstrap writes the Secret `kaval-approver` from it on every boot and on its 6-hour timer, like the database passwords.

One deliberate difference from the Slack and database Secrets: if the token cannot be read, the bootstrap **carries on** and writes no Secret. A gateway without a token is shut, which is the safe state; stopping the whole cluster's start-up for a login Secret would be worse. The test I wrote for that case found a real hole: a value of spaces passed the "not empty" check and made a Secret. The step now strips spaces first.

Read-only `terraform plan` for production: 2 to add (the parameter and the password), 3 to change (the node's read permission, the launch template's bootstrap text, the scaling group's template version), 0 to destroy, and no other drift. The group is parked at zero, so no server is touched. Nothing was applied. A new runbook, `approval-refused.md`, covers a 401 or 503 from the route, how to load the token into your shell without showing it, and how to rotate it.

Cost: $0 (a standard-tier SecureString parameter is free; the default key is free).

The node's start-up script is close to EC2's size limit (16,384 bytes once packed), and a guard test (`test_the_node_start_up_script_still_fits_the_ec2_limit`, line at 15,800) caught the first version of this step at 16,060. Rather than raise the guard, the step was made shorter and two comments that repeated a note already at the top of the same script were trimmed: it now packs to 15,744, 8 bytes more than before this change. The next addition to that script has to move something out first.
