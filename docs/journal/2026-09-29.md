# 2026-09-29

## The policy engine — `auto`/`ask`/`never`, and autonomy has to be earned (`KAV-42`, ADR-0017)

`kaval_agent.policy.classify()` shells out to `opa eval` against `policy/policy.rego`,
classifying every action `write_proposal` writes instead of the KAV-41-era hardcoded `ask`.
`never` matches keywords in the action's free-text type (`pvc`, `iam`, `ec2`, `billing`, ...)
plus a blanket rule for `blast_radius=account`, regardless of confidence. `auto` is gated by an
explicit, empty-by-default promotion list (`policy/promotions.json`) rather than computed
straight from `confidence > 0.9` — the rule cannot return `auto` for any input until a future ADR
adds an entry citing `outcome` evidence, which makes "nothing is born auto" an enforced property,
not just a sentence in `policy/README.md`.

OPA is evaluated by subprocess inside the agent process, not a standalone server — one caller
today (the agent); a shared server earns its cost once the executor (Phase 3) becomes a second
one. This corrects `architecture.toml`'s `policy` node, which had assumed a networked service
before either caller existed. The `opa` binary (checksum-verified, same download pattern as
gitleaks/Trivy) and `policy/` now ship inside the agent's Docker image; `ci.yml`'s `test` job
installs the amd64 build and runs `opa test policy/ -v`, and the `images` job checks the agent
image can actually reach it.

**Found while building it, not after.** The first version of `policy.rego` referenced
`data.promotions.promoted`; the first version of `policy_test.rego` proved "nothing is born
auto" by mocking `data.promotions` into existence with Rego's `with` construct. All 14 `opa
test` cases passed — including that one. Only `test_policy.py::test_nothing_is_born_auto`,
which calls `classify()` against the real, unmocked file on disk, caught that the real data path
was `data.auto_promotions` (a JSON data file's own top-level keys merge directly under `data`,
not the filename). Fixed in both files; `policy_test.rego`'s mocked version and `test_policy.py`'s
unmocked version now both prove the same claim, which is the point — a mocked test alone can't
tell you whether the real address is right. ADR-0017, Lab 12.

**A second bug, caught by CI rather than found in review.** `DEFAULT_POLICY_DIR` was computed
from `__file__`, four parents up — correct on a laptop with an editable install, wrong inside
the built image, where hatchling's wheel installs `kaval_agent` flattened into site-packages
rather than nested under `services/agent/`. The failure was quiet: `opa eval` against a
nonexistent directory exits non-zero, and `classify()`'s own fallback silently turned that into
`ask` for every action. The per-image CI check added for this story (running `opa eval` inside
the actual built container, not just the two test suites that both run from a checkout) failed
loudly instead. Fixed with `KAVAL_POLICY_DIR=/app/policy`, set in the Dockerfile and checked
before the `__file__`-relative fallback.

**Existing `action` rows are not reclassified.** `kaval_shared.models`'s own docstring says the
spine is append-only except two named columns; `policy_class` isn't one of them. The KAV-41-era
rows written under the hardcoded `ask` stopgap stay exactly as they are — rewriting them would
erase an honest record of what the system actually did that day. This reverses last night's
"Open threads" note, which had assumed reclassification was still on the table; ADR-0017 records
why it isn't.
